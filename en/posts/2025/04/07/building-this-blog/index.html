Building and Optimising a Hexo + Fluid + Obsidian Blog

1. Preface

The immediate reason I built this blog was that, while having dinner with a senior student some time ago, I saw the personal site he had made. I already knew that the relevant open-source projects were mature, so a thought struck me and I simply started working—not quite as dramatic as that, perhaps.

It also solved a problem that had troubled me for a long time: I had nowhere suitable to share things. I genuinely wanted to write more—to record the curious little projects I had experimented with, the works of art I had appreciated, and my own thoughts and feelings. While I still had time, I wanted to write longer essays that might protect my ability to think and express myself, rather than letting it disappear in the storm of short videos. But where could I write? Posting on Tieba, Zhihu, or Xiaohongshu did not appeal to me: I disliked the atmosphere of those platforms and had no desire to cover every statement in defensive disclaimers merely to suit it. QQ Space and WeChat Moments were not designed for long arguments; a short paragraph could neither satisfy my wish to express myself nor explain what I meant, and my WeChat contacts might not want to read it anyway. Making videos would be even worse: it would consume still more time and bring the culture of another online community into the calculation.

A personal blog meets these needs rather well. Here I can say whatever I want, describe what I think, and record what I wish to remember. After all, I am largely writing for myself, and almost nobody visits this site to read these articles. Besides, it is an amusing small project, is it not? The underlying software may be open source, but that does not prevent me from using the opportunity to learn something about front-end development.

The final paragraph of this preface is for any reader who happens to arrive. If you also want to build a personal blog of this kind, read on: I will record part of the construction process and the writing workflow I currently recommend.

2. Construction

Tools Used

  • Hexo: the blog framework, which may be understood as the skeleton of the site.
  • Fluid: the site’s theme. Its official documentation is detailed, so the configuration can simply follow that guide and needs no repetition here.
  • GitHub Pages: a convenient, free service for hosting static websites; one GitHub account can have one such site.
  • Obsidian: a text editor that becomes extremely convenient once configured. Its rich plugin system supports such tasks as importing templates and organising files through a directory structure.
  • Typora: a lightweight Markdown editor that adds rendering and keyboard shortcuts to what would otherwise be little more than Notepad.

Installation

Prerequisites

  • Node.js: a program capable of executing JavaScript code; more precisely, it is a JavaScript runtime.
  • Git: the well-known open-source distributed version-control system, designed to handle projects of any size efficiently. It is the Git underlying GitHub and can be regarded as a steward of file versions, supporting the storage, rollback, and upload of different revisions.

6. Optimisation

Folder-Based Category Trees through Automatic Classification

No project is perfect, and the workflow described above still felt awkward in several places. Categories were one example. Logically, when posts are written locally, their categories ought to follow the containment relationships among folders. Hexo’s native approach, however, requires the following metadata at the beginning of every post:

How am I supposed to manage this? Must I remember exactly where every file belongs in the directory tree, without getting a single character wrong? That merely creates more work. Categories are meant to make management easier; this reverses the whole purpose.

I therefore searched for another solution and found an open-source project:

  • xu-song/hexo-auto-category: Generate Categories Automatically for Each Post in Hexo

Installation and configuration can follow its official documentation. One point deserves attention: peculiar things may happen when a file has no category group—or so it appears.

Automatic Git Pushes

After writing the first few posts, I had to enter Git Bash and run hexo clean, hexo g, and hexo d manually every time. This soon became tiresome, which raised an obvious question: why not use an automation plugin?
