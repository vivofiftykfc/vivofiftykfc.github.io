Interrupts

Concepts

An interrupt occurs when a specified trigger condition, or interrupt source, arises while the main program is running. The CPU pauses the program currently being executed, turns to the interrupt service routine, and, once that routine is complete, returns to the point at which the original program was suspended.

Interrupt priority is needed when several interrupt sources request service at the same time. The CPU weighs their urgency and responds first to the more urgent source.

STM32 devices provide several categories of interrupt priority, and the priority of a particular interrupt is configured within this scheme.

Interrupt nesting occurs when a new source of higher priority requests service while an interrupt routine is already running. The CPU suspends the current interrupt routine, handles the new one, and then returns through the suspended routines in order.

Interrupts in STM32

The STM32 includes 68 maskable interrupt channels—interrupt sources, to put it another way. The figure of 68 is the upper limit for the F1 series, while the actual number depends on the device. These channels cover peripherals such as EXTI, which handles external or peripheral-controlled interrupts, as well as TIM, ADC, USART, SPI, I2C, and RTC.



The Nested Vectored Interrupt Controller (NVIC) manages interrupts in a unified manner. Each interrupt channel possesses 16 programmable priority levels. Priorities can be grouped and then divided further into pre-emption priority and response priority.

An interrupt with a higher pre-emption priority may interrupt another routine. One with a higher response priority is placed earlier in the queue. If both priorities are equal, the interrupt number determines the order.

NVIC interrupt priority is determined by four bits in the priority register, from 0 to 15. The four bits can be divided into the upper n bits for pre-emption priority and the lower 4-n bits for response priority.

EXTI and AFIO

EXTI monitors the level of a specified GPIO port. When the level on that GPIO changes, EXTI immediately submits an interrupt request to the NVIC. After arbitration by the NVIC, the CPU’s main program is interrupted and the CPU executes the corresponding EXTI interrupt routine.

If the CPU is a doctor, the NVIC is the ticket-calling machine, while EXTI is the nurses’ station that watches what is happening and decides when a number should be called and placed in the queue.

Supported trigger modes include rising edge, falling edge, both edges, and software triggering.

All GPIO ports are supported, but pins with the same number cannot trigger interrupts simultaneously. The reason is that AFIO acts as a multiplexer: for a given pin number, it can select only one source from GPIOA, GPIOB, and GPIOC.

AFIO mainly performs two tasks: remapping pins for alternate functions and selecting interrupt pins.

There are 16 GPIO_Pin channels, together with PVD output, the RTC alarm, USB wake-up, and Ethernet wake-up.

The response may take the form of either an interrupt response or an event response.

An interrupt response triggers the CPU to handle the request in the ordinary way, whereas an event response causes another peripheral to respond to the incoming event.

The last four channels were added because EXTI can wake the device from a low-power mode.

Rotary Encoder

A rotary encoder is a device used to measure position, speed, or direction of rotation. As its shaft turns, its output produces a square-wave signal corresponding to the rotational speed and direction. The speed and direction of the shaft can then be determined from the frequency and phase of that signal.

Common types include mechanical-contact, Hall-effect, and optical-grating encoders.

More specifically, locate the interrupt vector table in startup_stm32f10x_md.c. The names of the interrupt functions are fixed in advance.

The interrupt vector table is an array located at a fixed address in memory. Each entry, called an interrupt vector, stores the entry address of the interrupt service routine (ISR) associated with a particular interrupt number. When the CPU receives an interrupt request and obtains its number, the hardware automatically uses that number as an index into the table, reads the corresponding ISR address, and jumps to it. This arrangement enables fast and accurate interrupt handling.
